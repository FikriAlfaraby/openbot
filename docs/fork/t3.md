# T3 Code as the coding executor (items 3.1–3.1d)

Coding tickets run in T3 Code on the same VPS: one T3 thread and one git worktree per ticket.
OpenBot calls T3's own CLI, `t3 thread`, which needs no sign-in on the machine that runs T3 Code
(`docs/user/outside-agents.md` of T3 Code). The MCP path with OAuth is item 3.1d.

## CLI contract (read from T3 Code's source, `apps/server/src/cli/thread.ts`, 2026-11-02)

| Call | Result |
|---|---|
| `t3 thread start [--worktree <base>] [--branch <name>] [--title <t>] [--wait] --json -- <project> <message>` | Without `--wait`: the launch JSON with `threadId` and `runId`. |
| `t3 thread send [--wait] --json -- <thread> <message>` | Queues the message as the thread's next turn; never interrupts. |
| `t3 thread show --messages 3 --json -- <thread>` | `{ thread, messages }`. |
| any call with `--wait --json` | stdout `{ threadId, runId, status, reply, error }`, also when the run fails. |

Exit codes and ticket states (`src/backend/fork/t3/t3-cli.ts`):

| Exit | T3 meaning | Ticket state |
|---|---|---|
| 0, `status: completed` | the run completed | `review` (a person or the Router checks the result) |
| 0, no status | started or queued without `--wait` | `working` |
| 2 | the thread waits for a person's answer | `awaiting_human` |
| 1, or a timeout | the run stopped or failed, or the CLI failed | `failed`, with T3's error |

Refs for `--worktree` and `--branch` must be plain names; a message goes after `--`, so a message
that starts with a dash is not read as a flag.

## Users on the VPS

T3 Code must not run as root, and OpenBot's agents run as the service user `openbot`. Two setups:

1. **One user (simplest):** install and run T3 Code as the user `openbot`
   (`sudo -u openbot -H bash -c 'curl -fsSL https://t3.codes/install.sh | sh'`, then
   `sudo -u openbot t3 service install`). The command is `["t3"]`.
2. **Two users:** keep T3 under its own user and let `openbot` run it through `sudo -u t3user t3`
   with a narrow sudoers rule for `/usr/local/bin/t3 thread *`; or point `--base-dir` at that
   user's T3 home when its files are readable. Not tested.

The command, the T3 home and the project come from `fork-config.yaml` in item 3.1b.

## Worktrees and storage

Turn on **Settings → Worktrees → Cleanup** in T3 Code (it is off by default) and set
**Worktree location** to the block volume (`docs/fork/storage.md`).
